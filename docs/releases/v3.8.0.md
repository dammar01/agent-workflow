# v3.8.0

Lima tema: latensi workflow terukur per komponen (graph, reuse, effort, thread provider);
`/.verify-browser` mencatat metadata network dan mendahulukan selector yang terbukti;
telemetry per task (skill, edit, commit) tanpa instruksi prompt tambahan; `clean` membuang
lock guard sesi mati; dan research question menjadi record YAML yang ditautkan dua arah.
Tidak ada perubahan breaking pada konfigurasi. Hook baru `task-events` baru aktif setelah
`install`/`upgrade`.

**Perubahan perilaku yang terasa setelah upgrade:**

- Gate runtime auto-intent kini benar-benar aktif. `intent-gate-set` selama ini membaca
  field `user_prompt` yang tak pernah dikirim Claude Code, jadi marker gate tak pernah
  terpasang. Sekarang, sesudah prompt yang terpetakan ke command delegated, gather tool
  diblokir sampai `.workflow/run` dipanggil (escape: `WORKFLOW_LOCAL_MODE=1`).
- Mode `--only-command` kini membatasi seluruh blok workflow ke saat command dipanggil:
  chat biasa mengikuti CLAUDE.md user, termasuk gaya bahasa (caveman tak lagi default di
  mode ini).
- Template `settings.json` tak lagi menanam `model`, `enabledPlugins`,
  `extraKnownMarketplaces`, `effortLevel`, `permissions.defaultMode`. Install yang sudah
  ada tidak berubah; install baru tidak lagi mendapatkannya.

## Latensi dan telemetry

- Usage contract v3: `effort`, `provider_resumed`/`provider_thread_changed`, `reuse_outcome`,
  `graph_status`/`graph_ms`. `report` menambah `evidence_reuse`, `provider_cache`,
  `provider_threads`, `by_effort`, `graph_leads`. `by_effort` menghitung semua command dan
  median hanya dari nilai terukur. Lihat `docs/reference.md` (`report`).
- Refresh graph pindah sepenuhnya ke Stop hook `graph-refresh` dan berjalan terpisah dari
  turn; pembaca graph tidak menunggu lock (DEC-012, CASE-008).
- `verify-browser` mencatat sekali per command apakah refresh berjalan di sampingnya
  (`refreshing`/`available`/`absent`), tanpa lookup leads.
- Telemetry per task (DEC-015, direvisi DEC-020): `tasks.jsonl` diisi runtime (command
  delegated, dengan verdict yang dideklarasikan dan verdict turunan) dan hook `task-events`
  (skill lokal dimuat, edit file, commit yang memindahkan HEAD). `report` → `tasks`:
  `completed` hanya setelah verify yang verdict turunannya `pass`; commit dianjurkan sesudahnya
  tapi tidak menutup task. State `ready_to_commit` dan `unverified_closed` dihapus. Lihat
  `docs/reference.md` (Task telemetry) dan `docs/runtime-contracts.md` (Task events).

- Hook `task-events.ps1` tak lagi kehilangan event di Windows PowerShell 5.1 saat git menulis
  ke stderr (project tanpa git, repo dubious ownership); test hook kini memakai `powershell`
  5.1, sama dengan yang dipasang. Pembaca JSONL (usage, quality, tasks) melewati baris yang
  terpotong di tengah karakter multi-byte alih-alih membuat `report` crash; store knowledge
  e2e membaca dengan aturan yang sama.
- `graph-refresh`: refresh yang timeout tetap tercatat `timeout` dan graph yang tak bisa
  di-parse tak pernah dicatat `refreshed`; stale lock hanya dihapus bila token-nya masih sama
  (dua sesi tak lagi bisa menjalankan dua `graphify update` bersamaan); `target/` dilewati.
  Timeout membunuh seluruh pohon proses graphify, bukan hanya wrapper-nya.
- Hook `task-events` tidak lagi jalan di setiap `Read` dan `Bash` (~450 ms per spawn
  PowerShell di Windows; `Bash` kena dua kali). Skill dibaca dari prompt (`/.<name>`) dan
  tool `Skill`, commit dari HEAD yang berpindah antar turn (`UserPromptSubmit`/`Stop`).
  Event v2. Install mencabut registrasi lama dari `PreToolUse`.
- Usage contract v4: `e2e_stage` (`draft`/`run`) dan `browser_seconds`. Run browser yang
  berakhir sebelum review tidak lagi menulis baris usage — dulu baris tanpa `prompt_id`,
  provider, dan token itu dihitung statusline sebagai satu call tambahan dan oleh `report`
  sebagai verify yang dinilai serta verifikasi nol token di baseline. `report` membuang
  baris lama berbentuk itu; draft `verify-browser` keluar dari penyebut `evidence_reuse`.

## Install

- Install pertama ke CLAUDE.md/AGENTS.md menulis **hanya** blok marker; teks di luar marker
  tak lagi ikut tertulis dan tak bisa dibedakan dari teks user.
- `install.py --uninstall` (dry run, lalu `--apply`): cabut blok workflow dari tiap file
  instruksi dengan teks user tetap, file workflow yang tak diedit, serta hook dan
  `statusLine` workflow. Ber-receipt, jadi `--rollback` membatalkannya.
- Blok di `AGENTS.md` (opencode, codex, agy) hanya berlaku untuk call runtime (instruksi
  dibuka `[WORKFLOW_AGENT]`); memakai provider itu langsung tak lagi ikut aturan second agent.
- Dokumentasi: `docs/team-guide/installation.md`, `docs/team-guide/whats-included.md`;
  `docs/reference.md` memuat tabel semua flag, target, dan hook. README kini menampilkan dua
  baris install (`--auto-intent` / `--only-command`), uninstall, dan rollback.
- Marker blok yang tak berpasangan (START tanpa END atau sebaliknya) membuat install file itu
  ditolak dengan pesan jelas, bukan menambah blok kedua.
- Uninstall membersihkan `settings.json` (juga yang ber-BOM) **sebelum** menghapus script hook;
  bila settings tak bisa dibaca, script tetap ada sehingga hook tak menunjuk file hilang.
- `doctor` memperingatkan header lama `Personal Global Config (v…)` di luar marker
  `~/.claude/CLAUDE.md`: sisa install lama, kini teks user, aman dihapus manual.

## Codex di Windows

- Kegagalan sandbox Windows codex (`windows sandbox failed ...`) kini `error_type:
  sandbox_unavailable` dengan langkah perbaikan berurutan, bukan `unknown` (CASE-015).
  Runtime tidak menurunkan sandbox.
- Versi codex tercatat di meta call, baris usage (`provider_version`), dan `doctor`.
- `thread_changed` (codex, agy) tidak lagi menyala untuk call resume yang gagal sebelum
  menyebut thread apa pun.
- Rilis provider yang diuji: `stable_version` per provider di `config/providers.py`
  (opencode 1.18.34, codex 0.154.0, agy 1.1.13). Versi dibaca untuk **semua** provider; usage
  row membawa `provider_version_status` (`stable`/`untested`/`unreadable`) dan `doctor`
  memperingatkan rilis `untested`. Advisori, tak memblokir. Bisect di Windows: codex
  sesudah 0.154.0 sampai 0.160.0 gagal me-resume thread (`sandbox_unavailable`), thread
  baru tetap jalan (CASE-016). Pin kembali: `npm i -g @openai/codex@0.154.0`.
- `codex --version` dan pembacaan versi provider lain dibatasi waktu dan membunuh pohon proses
  saat timeout (shim `.cmd` di Windows).

## `/.verify-browser`

- Metadata request terurut untuk setiap request — tipe, ukuran, durasi, beda antar-run —
  tanpa body atau header (DEC-014).
- Selector yang terbukti (`data-e2e` yang dikutip dari source, atau yang sudah lolos run
  sebelumnya) diurutkan di atas role dan label; yang gagal diturunkan lalu dipensiunkan
  (DEC-016). Hanya kandidat yang benar-benar dicoba browser yang bisa gagal: step yang gagal

  `proven` yang hilang dari halaman stabil diklasifikasi `app`, seperti selector bersumber.
- Pencatatan usage diaudit ulang (draft + continuation + repair, run + continuation review):
  satu row per invocation, token per row sama dengan laporan provider, `browser_seconds` hanya
  di row terakhir, hitungan call statusline = `report.calls`. Tak ada salah hitung sejak
  8d2d42b; baris hantu lama (209, sebelum 8d2d42b) tetap disaring `report`.

## Verify

- Second agent tak lagi menjalankan test. Main agent memilih test dari diff dan dependents ke
  `verify/tests.json` per sesi; runtime menjalankannya (hanya prefix di
  `commands.verify_test_commands`, tanpa shell) dan menulis hasilnya ke `[VERIFICATION]`:
  test gagal = blocking, request tak ada atau command ditolak = `not_verified`. **Perubahan
  perilaku:** verify tanpa `tests.json` kini `incomplete`, dan allowlist default kosong —
  isi `commands.verify_test_commands` di `.workflow/config.json` tiap project.
- Usage: `tests_requested`, `tests_run`, `tests_failed`, `tests_seconds`.
- Pengerasan: `reason`/`command`/`detail` dari `tests.json` tak bisa lagi memalsukan section
  `[VERIFICATION]` lewat newline (verdict `incomplete` sempat bisa jadi `pass`); timeout test
  membunuh seluruh pohon proses (dulu verify bisa menggantung selamanya di Windows sambil
  memegang lock sesi); `tests.json` baru dikonsumsi sesudah hasil digabung (run pemulihan masih
  menemukannya); timeout boolean diabaikan.
- Allowlist kosong: baris prompt "jangan jalankan test runner" tak dikirim, dan `doctor`
  memperingatkannya. Gate hook mengizinkan main_agent membaca `git diff --name-only`/`--stat`
  dan `.workflow/config.json` serta menulis `verify/tests.json` sebelum `.workflow/run verify`
  — dulu skill menyuruh memilih test dari diff sementara gate memblokirnya.

- Section "tidak ada temuan" diterima dalam ejaan yang ditulis agent (`none.`, `none; all
  clean`, `tidak ada`, …) sehingga verify bersih tidak lagi jadi `fail`; continuation meminta
  `- none` (DEC-018, CASE-009). Di reviewer E2E, item multi-baris tetap hanya menerima bentuk
  lama, sehingga `- none.` tidak menyembunyikan temuan di baris berikutnya.

## Kontrak perhitungan benchmark

- Registry metrik (`core/audit/metrics.py`, dirender di `docs/evaluation/metrics.md`): tiap
  angka punya ID dan versi (`outcome.solved@1`), definisi, penyebut, aturan data hilang, dan
  konvensi statistiknya. Istilah yang dulu dipakai bertumpuk ("task", "saved") kini ID terpisah.
  Rumus yang ada tidak diubah: `measure_task_outcomes` menghasilkan angka CASE-012 yang sama
  persis (97 task, 68 solved).
- `report()`, `measure_real_use.py`, dan `measure_task_outcomes.py` mencetak blok `provenance`
  (versi metrik, commit tool, parameter, hash input tanpa path). Threshold `measure_task_outcomes`
  yang tadinya hard-coded kini flag dengan default yang sama.
- Aturan riset baru (CONTRACT.md §15, DEC-026): angka dari metrik terdaftar dikutip sebagai
  `<id>@<version>` beserta provenance-nya.
- Tools ukur untuk semua user (DEC-027): siapa pun yang memasang workflow bisa menjalankan
  `measure_real_use.py`/`measure_task_outcomes.py` atas project-nya sendiri; `--export <file>`
  menulis agregat + provenance yang boleh dibagikan, ditolak bila memuat path atau nama project.
  Panduan: `docs/team-guide/measure-your-use.md`. Hitung ulang tetap hanya di mesin pemilik
  data.
- `outcome.context_saved@2`: definisi diperbaiki jadi rumus yang memang dijalankan (fresh −
  returned; reasoning dilaporkan terpisah) dan test kini mencocokkan implementasi, bukan hanya
  docs. Bersama `real_use.delegated_call@2`: satu usage row milik satu transcript (yang paling
  awal mengikat session id-nya). Pada semua data sampai 2026-10-04 hasilnya identik dengan @1
  (tak ada session id terikat dua kali).
