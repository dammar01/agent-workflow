# v3.8.0

Lima tema: latensi workflow terukur per komponen (graph, reuse, effort, thread provider);
`/.verify-browser` mencatat metadata network dan mendahulukan selector yang terbukti;
telemetry per task (skill, edit, commit) tanpa instruksi prompt tambahan; `clean` membuang
lock guard sesi mati; dan research question menjadi record YAML yang ditautkan dua arah.
Tidak ada perubahan breaking pada konfigurasi. Hook baru `task-events` baru aktif setelah
`install`/`upgrade`.

**Perubahan perilaku yang terasa setelah upgrade:**

- Gate runtime auto-intent kini benar-benar aktif. `intent-gate-set` selama ini membaca
  field `user_prompt` yang tak pernah dikirim Claude Code, jadi marker gate tak pernah
  terpasang. Sekarang, sesudah prompt yang terpetakan ke command delegated, gather tool
  diblokir sampai `.workflow/run` dipanggil (escape: `WORKFLOW_LOCAL_MODE=1`).
- Mode `--only-command` kini membatasi seluruh blok workflow ke saat command dipanggil:
  chat biasa mengikuti CLAUDE.md user, termasuk gaya bahasa (caveman tak lagi default di
  mode ini).
- Template `settings.json` tak lagi menanam `model`, `enabledPlugins`,
  `extraKnownMarketplaces`, `effortLevel`, `permissions.defaultMode`. Install yang sudah
  ada tidak berubah; install baru tidak lagi mendapatkannya.

## Latensi dan telemetry

- Usage contract v3: `effort`, `provider_resumed`/`provider_thread_changed`, `reuse_outcome`,
  `graph_status`/`graph_ms`. `report` menambah `evidence_reuse`, `provider_cache`,
  `provider_threads`, `by_effort`, `graph_leads`. `by_effort` menghitung semua command dan
  median hanya dari nilai terukur. Lihat `docs/reference.md` (`report`).
- Refresh graph pindah sepenuhnya ke Stop hook `graph-refresh` dan berjalan terpisah dari
  turn; pembaca graph tidak menunggu lock (DEC-012, CASE-008).
- `verify-browser` mencatat sekali per command apakah refresh berjalan di sampingnya
  (`refreshing`/`available`/`absent`), tanpa lookup leads.
- Telemetry per task (DEC-015, direvisi DEC-020): `tasks.jsonl` diisi runtime (command
  delegated, dengan verdict yang dideklarasikan dan verdict turunan) dan hook `task-events`
  (skill lokal dimuat, edit file, commit yang memindahkan HEAD). `report` → `tasks`:
  `completed` hanya setelah verify yang verdict turunannya `pass`; commit dianjurkan sesudahnya
  tapi tidak menutup task. State `ready_to_commit` dan `unverified_closed` dihapus. Lihat
  `docs/reference.md` (Task telemetry) dan `docs/runtime-contracts.md` (Task events).

- Hook `task-events` tidak lagi jalan di setiap `Read` dan `Bash` (~450 ms per spawn
  PowerShell di Windows; `Bash` kena dua kali). Skill dibaca dari prompt (`/.<name>`) dan
  tool `Skill`, commit dari HEAD yang berpindah antar turn (`UserPromptSubmit`/`Stop`).
  Event v2. Install mencabut registrasi lama dari `PreToolUse`.
- Usage contract v4: `e2e_stage` (`draft`/`run`) dan `browser_seconds`. Run browser yang
  berakhir sebelum review tidak lagi menulis baris usage — dulu baris tanpa `prompt_id`,
  provider, dan token itu dihitung statusline sebagai satu call tambahan dan oleh `report`
  sebagai verify yang dinilai serta verifikasi nol token di baseline. `report` membuang
  baris lama berbentuk itu; draft `verify-browser` keluar dari penyebut `evidence_reuse`.

## Install

- Install pertama ke CLAUDE.md/AGENTS.md menulis **hanya** blok marker; teks di luar marker
  tak lagi ikut tertulis dan tak bisa dibedakan dari teks user.
- `install.py --uninstall` (dry run, lalu `--apply`): cabut blok workflow dari tiap file
  instruksi dengan teks user tetap, file workflow yang tak diedit, serta hook dan
  `statusLine` workflow. Ber-receipt, jadi `--rollback` membatalkannya.
- Blok di `AGENTS.md` (opencode, codex, agy) hanya berlaku untuk call runtime (instruksi
  dibuka `[WORKFLOW_AGENT]`); memakai provider itu langsung tak lagi ikut aturan second agent.
- Dokumentasi: `docs/team-guide/installation.md`, `docs/team-guide/whats-included.md`;
  `docs/reference.md` memuat tabel semua flag, target, dan hook.

## Codex di Windows

- Kegagalan sandbox Windows codex (`windows sandbox failed ...`) kini `error_type:
  sandbox_unavailable` dengan langkah perbaikan berurutan, bukan `unknown` (CASE-015).
  Runtime tidak menurunkan sandbox.
- Versi codex tercatat di meta call, baris usage (`provider_version`), dan `doctor`.
- `thread_changed` (codex, agy) tidak lagi menyala untuk call resume yang gagal sebelum
  menyebut thread apa pun.

## Test

- Suite tak lagi bergantung pada pilihan provider mesin: seed `config/second_agent.seed.json`
  (git-ignored) ber-provider codex membuat `scenario` dan `continuation` gagal di mesin itu
  saja. Workspace test kini selalu dari `second_agent.example.json` (`test-isolation`).

## `/.verify-browser`

- Metadata request terurut untuk setiap request — tipe, ukuran, durasi, beda antar-run —
  tanpa body atau header (DEC-014).
- Selector yang terbukti (`data-e2e` yang dikutip dari source, atau yang sudah lolos run
  sebelumnya) diurutkan di atas role dan label; yang gagal diturunkan lalu dipensiunkan
  (DEC-016).

## Verify

- Section "tidak ada temuan" diterima dalam ejaan yang ditulis agent (`none.`, `none; all
  clean`, `tidak ada`, …) sehingga verify bersih tidak lagi jadi `fail`; continuation meminta
  `- none` (DEC-018, CASE-009). Di reviewer E2E, item multi-baris tetap hanya menerima bentuk
  lama, sehingga `- none.` tidak menyembunyikan temuan di baris berikutnya.

## Workspace

- `clean` menghapus `sessions/<id>/runtime/lock.guard` milik sesi tanpa runtime lock hidup;
  guard yang sedang dipegang tetap. Aman terhadap race di Windows (delete ditolak OS) dan
  POSIX (pemegang menunggu membuka ulang path) (DEC-013, CASE-007).

## Research

- Research question menjadi record `RQ` YAML dengan link dua arah ke record yang melayaninya;
  validator menolak record v1 baru di luar daftar beku `FROZEN_V1`, dan template naik ke
  schema v2 (DEC-017).
- Record baru: DEC-012..DEC-018, CASE-006..CASE-010, RQ-01..RQ-15. Semua keputusan
  `implemented`, tidak ada yang `validated`. Masih draft: H-004, H-008, H-009, H-010, EXP-004.
- Schema v3 (DEC-019): status RQ biner `answered | unanswered`; RQ `answered` wajib punya
  record `validated` dan blok `decision` dari wawancara kritis maintainer. DEC `validated`
  wajib `uses` ≥ 2, `consistent`, `maintainer_decision`, dan pengukuran (run clean atau
  angka telemetry). Record v2 dibekukan (`FROZEN_V2`). DEC-001/007/010/011 dievaluasi ulang
  dan tetap `validated`; RQ-15 `answered`, 15 RQ lain `unanswered`.
