# v3.8.2

Rilis penutup sebelum feature freeze: tidak ada fitur baru, hanya jalur gagal yang
sebelumnya diam atau longgar. Second agent codex ternyata bisa menulis file lewat tool edit
bawaannya walau berjalan `--sandbox read-only` — kini ditutup dan dibuktikan ulang terhadap
CLI sungguhan. Setiap provider menyatakan boundary baca/tulis yang benar-benar ditegakkan,
dan agy mendapat peringatan tulis. Thread id provider tak lagi hilang diam-diam di Windows,
dan jalur integritas (manifest, `install --check`, scrub artefak e2e) gagal tertutup. Kontrak
plan/approval DEC-046 dari 3.8.1 ikut terpasang. Tidak ada perubahan breaking pada
konfigurasi; prompt bundle baru aktif setelah `install`/`upgrade`.

**Perubahan perilaku yang terasa setelah upgrade:**

- Call codex membawa `-c approval_policy="never"`: patch file oleh codex ditolak di call
  baru maupun resume.
- `/.doctor` dengan agy menampilkan `WARNING` kedua: agy bisa menulis ke project.
- Hasil delegated membawa `meta.provider_boundary`; untuk agy juga `meta.provider_write_warning`.
- Storage session yang tak bisa ditulis menggagalkan call **sebelum** provider jalan
  (`session_capture_failed`); kehilangan thread di tengah run muncul sebagai
  `meta.session_persisted: false`.
- `install --check` melaporkan entri manifest yang file sumbernya sudah dihapus; `doctor`
  menjadikan entri manifest rusak sebagai issue.
- Artefak e2e yang tak bisa di-scrub dihapus dan ditahan dari report serta reviewer.
- Fitur baru tanpa plan aktif diarahkan ke `/.plan`; hanya `/.execute -y` dari user yang
  dihitung persetujuan (DEC-046).

## Boundary tulis provider (DEC-048, CASE-019)

`--sandbox read-only` codex hanya membatasi perintah shell; tool edit file-nya (`apply_patch`)
diatur approval policy. Adapter kini mengirim `approval_policy="never"` di `exec` dan
`exec resume`. Tiap bundle provider menyatakan `boundary: {reads, writes}`; doctor dan setiap
hasil delegated membaca pernyataan yang sama. Probe opt-in membuktikan ulang terhadap CLI
sungguhan dan memakai kuota codex.
Detail: [docs/reference.md](../reference.md), "Memilih provider";
[docs/runtime-contracts.md](../runtime-contracts.md).

## Thread provider dan integritas (DEC-049)

Record session dan job ditulis lewat `atomic_write_json`: nama temp unik dan `os.replace`
diulang saat Windows menolak karena file sedang dibaca proses lain. Executor menguji storage
sebelum provider jalan, mengulang simpan setelah run, dan menamai kehilangan yang tersisa.
Manifest rusak, sumber manifest yang hilang, dan artefak yang gagal di-scrub tak lagi lolos
diam-diam.
Detail: [docs/runtime-contracts.md](../runtime-contracts.md).

## Test

Suite default kini menjalankan dua check yang sebelumnya terdaftar di `SUITES` tetapi tak
dipanggil `scenario` (`error-types`, `redaction-boundary`); tanpa itu guard registrasi
menghentikan suite sebelum test mana pun jalan. Check baru: `session-persistence`,
`atomic-write-held`, `provider-boundary`, `manifest-malformed`, dan `codex-write-probe` (opt-in).

## Diketahui, belum ditangani

- Sekitar sepuluh writer runtime lain (fact store, graph index, knowledge e2e, ledger
  installer, dan lainnya) masih memakai temp-dan-replace sendiri tanpa retry.
- Pesan `init` untuk codex masih menulis bahwa `--sandbox read-only` membatasi tulis, tanpa
  menyebut `approval_policy`.
- Reviewer `/.verify` tak melihat `runtime_tests`, sehingga verify yang bersih bisa berakhir
  `incomplete`.
- `claude -p` tak bisa menyelesaikan command delegated: runner wajib background task, dan
  proses keluar sebelum task selesai (CASE-020).
