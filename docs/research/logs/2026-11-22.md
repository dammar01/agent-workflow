# Research log — 2026-11-22

In discussions on 21–22 November 2026, the maintainer selected **an external problem-solving environment for agents** as Exoma's product direction. The model interprets the problem and reasons about a solution. Exoma supplies the tools, evidence, project context and execution state it can use. The intended benefit is that an agent facing a later task can recover the evidence and reasoning behind an earlier decision and judge whether it applies again.

This dated account records the maintainer's intent. The discussions included AI-assisted reasoning and a maintainer review of Exoma. The version descriptions below reflect what was discussed at the time. Exoma's source and release records are authoritative for what shipped. [Exoma repository](https://github.com/dammar01/Exoma)

## What should carry over to a later task?

**Operational continuity** lets an interrupted job resume safely. It requires evidence about the job, its owner and the process that held its lock. **Problem-solving continuity** lets an agent recover why an approach was chosen, what happened when it was tried, and under which conditions the outcome is relevant. Recovering a job establishes the former. Establishing the latter requires observing how earlier experience affects work on a later task.

The maintainer grouped this direction into four areas. **P2, Cognitive Extension**, is the objective. **P4, Adaptive Problem-Solving Environment**, is the setting in which the agent pursues it using tools, evidence, hypotheses and feedback. **P1, External Memory**, preserves applicable context across tasks. **P3, Epistemic Infrastructure**, preserves the source of a claim, its limits and subsequent corrections. These labels describe the discussion's priorities.

The discussion traced how experience might become reusable through expansion, evidence validation, application, correction and consolidation. Each step calls for a different observation. Retrieving a correction shows it was available. Incorporating it into stored knowledge requires an update. Showing that it improved a procedure requires evidence from subsequent use. An interaction alone supplies no basis for automatically promoting it into project knowledge.

## Who decides what the evidence means?

The human sets the problem and authorizes actions. Evidence sources supply observations, and the secondary agent can gather them within a bounded assignment. The primary agent interprets those observations, evaluates the proposed solution and identifies uncertainty. The runtime enforces permissions, contracts and state transitions and retains provenance. A passing runtime check establishes that its rule was satisfied. Whether the solution addresses the user's problem requires separate evidence, especially when the primary agent also evaluates its own work.

| Development line | Focus and status in the maintainer's account |

| v1.2.x | Controlled adaptation and operational continuity. The v1.2.0 review covered risk-based test selection and browser retries that preserve verification obligations. The v1.2.1 discussion covered stale-job recovery after a verified reboot using owner and process-generation evidence. |
| v1.2.2 | **Proposed handoff** for operational efficiency and diagnostic reliability. The handoff covered the five items below. |
| v1.3.x | **Selected implementation direction.** The maintainer chose StateM as a reference for using prior experience and procedures on subsequent tasks. The discussion left component choices and implementation status to Exoma engineering. |

The v1.2.2 handoff proposed five changes with explicit limits.

1. Reduce duplicated instruction context while preserving approvals, session binding, safety rules and output contracts.
2. Bound Git observation time. Preserve independent skill and edit events on failure, and append each commit event before advancing its snapshot. Task reconstruction depends on synchronous event order.
3. Explain runner-gate refusals and count them without retaining raw prompts, commands or secrets.
4. Have the doctor inspect installed instructions and report observed failures. Legacy-header cleanup would use exact matches, a preview and explicit confirmation.
5. Report stored data size and age so operators can preview and authorize retention actions while protecting active sessions and diagnostic evidence.

The handoff deferred asynchronous capture, latency-only hook consolidation, automatic broad cleanup, graph-refresh ownership changes, unsupported Defender exclusions, and removing low-impact tooling solely to save tokens. Experience-related StateM work was assigned to v1.3.x.

## Relevance to agent-workflow

The closest existing research question asks whether persistent knowledge reduces repeated exploration and changes later behaviour. A later agent might retrieve an earlier procedure, check the conditions under which it worked, and use it to avoid repeating an investigation. The account supplies a reason to look for that sequence. It supplies no observation of a later task doing so. The benefit remains unmeasured. [RQ-06](../questions/RQ-06-persistent-knowledge-reduces-reexploration.yaml)

The project's primary question remains when another delegated execution improves a task enough to justify its token, latency, human-intervention and coordination costs. The November discussions made no comparison across delegation levels. Engineering can proceed on its own rationale, and later evaluation can establish what the change achieved.
